# Global Technical Constraints

- Target Environment: SAP ECC 6.0 EHP8, NetWeaver 7.50, ABAP 7.50. Database: NOT SAP HANA (traditional DB — MaxDB, Oracle, SQL Server, or DB2).
- ABAP Rules: Strict classic ABAP syntax (release 7.50). Inline declarations (DATA(x), FIELD-SYMBOL(<fs>)) are permitted. Constructor expressions (VALUE, NEW, COND, SWITCH, CORRESPONDING, CONV, REF, REDUCE, FILTER) are permitted. String templates |...| are permitted. NO ABAP Cloud / RAP / Steampunk / EML syntax. NO AMDP (ABAP-Managed Database Procedures require HANA). NO XCO library. NO FINAL(x) immutable inline declarations (requires ABAP 7.57+).
- CDS Rules: Classic ABAP CDS view entities (DEFINE VIEW ENTITY, available since ABAP 7.40) ARE permitted — they compile to a standard DB SQL view and do not require HANA. NOT permitted: HANA-specific CDS built-in SQL functions, OLAP/analytical annotations, or any CDS feature that requires HANA's calculation engine or code pushdown. When unsure if a CDS feature is HANA-specific, verify before use or prefer a classic SE11 view / Open SQL JOIN.
- SQL Rules: Use Open SQL (not ABAP SQL new syntax). No WITH (CTE) — requires HANA. No HIERARCHY expressions. Use FOR ALL ENTRIES or JOINs for multi-table reads. Aggregate functions (COUNT, SUM, AVG, MIN, MAX) are available.
- DDIC Rules: Use classical Dictionary objects (SE11) — tables, structures, data elements, domains, search helps, lock objects, table types. Classic CDS view entities are permitted as a read-view layer on top of these (see CDS Rules above); no HANA-specific DDL artifacts.
- Enhancement Rules: Use classic BAdIs, user-exits, enhancement spots, and implicit/explicit enhancement points. No new-style RAP-based extensibility.
- Python MCP Rules: Flat input schemas for tools (no top-level Union, oneOf, or anyOf).
